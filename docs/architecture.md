# 工程架构约定

v0.2 已接入参考工程的真实 L1/L2 和进化策略；核心边界、历史兼容与运行参数见 `core-integration.md`。下文的“首版”段落记录 v0.1 基线，演示模式继续按该实现执行。

## 契约与数据

Pydantic 是契约唯一来源，生成 JSON Schema 和 TypeScript。统一 kg/m/s/rad/N，能量存储为 Wh、功率为 W。机体系 FRD、世界坐标约定 NED，页面俯视图仅做展示变换。

DroneIR 只描述确定构型，搜索空间属于 DesignGoal。哈希使用类型规范化 JSON、排序和 SHA-256，不含实验 ID、名称与谱系。当前不对旋翼排列置换等物理等价关系额外归一化。

实验保存请求快照；候选唯一键为 `(run_id, proposal_index)`；评估唯一键为 `(candidate_id, level)`；Attempt 记录每次派发。缓存保存应用用户约束前的原始评估，命中后按当前目标重新筛选。

## 状态与恢复

状态流：QUEUED → RUNNING → COMPLETED；QUEUED/RUNNING 可暂停为 PAUSED，PAUSED 恢复为 QUEUED；上述活动状态均可 CANCELLED。

COMPLETED 表示编排结束，需结合 stop_reason 区分搜索完成和预算耗尽。候选失败区分约束淘汰、执行崩溃、不支持及预算跳过。

API 只操作持久化状态；独立 Worker 在短事务中选择实验、推进候选游标、预占预算并登记尝试。评估在事务外执行，随后事务提交结果、缓存、候选状态和事件。

OS 文件锁保证每个数据库只有一个编排 Worker。异常退出释放锁，重启时将遗留尝试标记 INTERRUPTED，保留已消耗预算，并从候选未完成层级继续。执行语义为至少一次，归档通过唯一键去重。CRASHED/TIMEOUT 不进入缓存。

随机搜索由 `seed + proposal_index + optimizer_version` 决定，无需保存 RNG 内部状态；observe 暂不改变随机策略。自适应优化器接入时，需增加可靠检查点和观测去重。

## 缓存与报告

缓存键包含 IR 哈希、Schema 版本、完整场景、评估器层级/实现版本及随机种子。评估公式或依赖行为改变须升级评估器版本。

报告包含配置快照、全部候选 IR、指标、约束违反、验证等级、评估版本和执行尝试。数据库保存全部事件，API/报告只返回最近 100 条事件。当前没有真实遥测/轨迹产物。

## 物理边界

L1 首版计算质量合成、推重比、简化悬停功耗、放电功率和桨叶间距。功耗采用简化动量模型及固定效率/辅助功耗。未实现完整控制分配、配平、重心与惯量合成。

L2 首版使用确定性的合成跟踪误差，用于验证漏斗、数据传递和前沿计算，必须保持 DEMO 标记。

## 后续迁移

阶段二补齐完整惯量张量、部件质量归属、配平与动力学，并升级契约及评估器版本。按吞吐需求将 Store 事务迁移到 PostgreSQL，通过持久化任务与 outbox 接入队列；遥测文件写对象存储。

分布式 Worker 需要租约、心跳、去重及超时回收，不能复用单机文件锁。L3 在派发前检查构型、飞控与编译器支持能力。
