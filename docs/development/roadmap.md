# 当前能力与开发路线

## 阶段状态

| 阶段 | 状态 | 当前成果 |
|---|---|---|
| 一：软件闭环 | 已完成 | 契约、独立 API/Worker、持久化、预算、缓存、恢复、工作台和导出 |
| 二：动力学与寻优 | 部分完成 | L1 配平、6-DOF/PID、风场/故障/随机化、进化搜索、参数详情与轨迹 |

实现细节与边界见 [工程架构](../architecture/overview.md)，已执行检查见 [验证记录](../quality/validation.md)。

## 阶段二后续

| 工作 | 下一步 | 验收标准 |
|---|---|---|
| 模型可信度 | 扩展质量分布、模型标定、步长敏感性及独立参考算例 | 误差与适用范围有定量证据 |
| 控制分配 | 从秩和悬停配平扩展控制裕度与可达域 | 不可行或裕度不足方案可解释淘汰 |
| 优化算法 | 接入 Optuna/PyMOO，完善自适应策略检查点 | 预算内优于基准且可重放恢复 |
| 多场景评价 | 联合任务、场景聚合及随机统计 | 指标聚合方式明确、约束无漏检 |
| 遥测与回放 | Parquet、产物管理和 3D 回放 | 时间与坐标一致，产物可追踪 |
| 计算与存储 | 按吞吐需求引入进程池、PostgreSQL、对象存储及队列 | 并发预算、幂等、租约及恢复验证通过 |

当前对角机身惯量与质点部件合成、随机化和进化策略已可运行，不代表上述扩展全部完成。

## 阶段三实施顺序

1. 选择受支持四旋翼，锁定 PX4/Gazebo 的可运行组合。
2. 实现 DroneIR 到模型和飞控参数的 Compiler，增加构型能力检查。
3. 构建无头 Linux 容器，管理资源、端口、超时、日志与清理。
4. 按预算、排名和多样性挑选 Top-K 晋级。
5. 对齐 L2/L3 的任务、时间、指标和验证等级。
6. 接入容器队列、遥测归档与完整验证报告。

验收需完整覆盖模型生成、SITL 启动、任务执行、结果归档和容器清理。不支持的构型应在派发前明确拒绝。
